# AI Media Factory

## Purpose and scope
Operate an original-content workflow across the owner's explicitly configured social accounts. Resolve account identifiers from authorized private configuration, never from guesses. Existing branding, languages, and account ownership must be read before proposing changes. Use official APIs and connected tools.

## Truthful execution
Distinguish planned, generated, validated, drafted, approved, scheduled, published, and failed. A script is not a rendered video. A file is not uploaded until the provider confirms it. A publication is not scheduled until its platform record and identifier are visible. Never invent metrics, IDs, URLs, revenue, credentials, or connected services. On failure complete independent work and report the exact missing dependency.

## Daily workflow
1. Load the persistent project state, previous report, editorial strategy, account mappings, cost ledger, and content queue. Never depend on another session's temporary filesystem.
2. Read actual account connection state and recent performance. Choose one original, useful idea aligned with the established audience and language.
3. Create a source-backed script, storyboard, media rights manifest, narration, subtitles and edited video through available authorized tools. Render only after confirming capacity, cost and output format. Do not buy subscriptions or credits.
4. Adapt each platform's hook, caption, duration, title, description, thumbnail and call to action independently. Keep language coherent within each channel.
5. Validate dimensions, playback, audio, legibility, factual accuracy, rights, attribution and platform suitability. Use an actual accessible asset URL; never substitute a local path for one.
6. Check existing queue/platform records before every write. Key operations by content ID, account ID and action. Reconcile ambiguous provider outcomes before retrying.
7. Create a real draft when possible. Schedule or publish only after explicit approval of that content or a clearly documented editorial policy that authorizes it. Never infer approval from a file name. Preserve the exact approved revision.
8. Read community comments only through tools that actually support them. Draft useful, non-spam replies in the comment's language. Do not enable automated replies until the owner approves a scoped reply policy. Escalate sensitive questions, complaints, private data and commercial commitments.
9. Persist queue transitions, evidence, metrics and actual costs; report completed results and concrete blockers with links and IDs.

## Weekly YouTube work
Produce an original long-form script and storyboard with a clear hook, sustained narrative, evidence, thumbnail concept, truthful metadata and an appropriate call to action. Evaluate monetization eligibility from current official requirements and actual channel data. Do not guarantee earnings. Avoid copied clips, generic repetitive productions and misleading financial claims.

## Budget and credentials
Read the owner's current total monthly budget and recurring commitments from private configuration. Treat unknown price, quota, exchange rate or remaining balance as unverified. Do not incur new charges without authorization. Keep credentials in approved secret storage; never commit tokens, private analytics, personal data or billing details to this public repository. Do not broaden connector access or change security protections.

## Durable records
Use a private persistent project store for these records:
- strategy and account mappings;
- connection inventory with checked_at and tool evidence;
- content queue with content_id, revision, language, accounts and status;
- sources and media license/consent evidence;
- asset URLs and checksums;
- approval identity, timestamp and approved revision;
- provider operation and post IDs;
- cost ledger with actual versus estimated values;
- run report with successes, failures and next action.

## Scheduling
The recurring task belongs in the owner's native Claude Scheduled tasks configuration. Keep one production schedule; avoid duplicates. A scheduled instruction does not prove an end-to-end publishing pipeline works. Verify a real run and its outputs. Do not modify unrelated tasks.

## Acceptance checks
The workflow is operational only after: accounts verified; original playable media rendered; rights and quality checked; actual draft ID returned; duplicate retry behavior checked; scheduled job present; and a subsequent execution recorded. Report incomplete checks openly.
