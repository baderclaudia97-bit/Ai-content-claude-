# Evidence-led script

Work without generation, purchases, publication or replies. Use only sources and tools already authorized for the project.

1. Read the private episode brief. Identify one audience problem, one useful takeaway and the intended language. Do not switch markets or languages without a brief.
2. Check unstable or specific facts against current primary sources: official product documentation, original research, first-party demonstrations or original data. Open the source before relying on it. Record title, URL, access date and the exact claim supported.
3. Separate a demonstrated result, a source's reported result, an illustrative example and an untested hypothesis. Label examples as examples. Do not transform a hypothetical saving into a measured saving.
4. Write a spoken hook that introduces a concrete problem. Build a short causal story that can be shown as action. End with a useful decision or next step. Avoid generic motivational narration, fabricated testimonials and income guarantees.
5. For a 10–15 second sample, target roughly 20–32 spoken English words, then adjust to measured narration duration. Do not claim exact timing until audio exists. Keep on-screen copy separate from narration.
6. Remove any claim that cannot be supported. If the story depends on unavailable evidence, report the missing evidence and supply a clearly labelled illustrative alternative.

Deliver `script.md` with:

- Episode/run ID and version, audience, language and single takeaway.
- Exact narration, estimated duration, and compact on-screen copy.
- Claim table: claim, status (`verified`, `reported`, `illustrative`, `unsupported`), source URL and location, access date, limitations.
- A shot-friendly action for each sentence and any pronunciation notes.
- Missing decisions or evidence, plus actual saved file reference or provider document ID.

Do not claim the file was saved unless a write returned a usable reference. Do not write private project deliverables into the public plugin repository.
